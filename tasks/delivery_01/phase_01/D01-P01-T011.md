## Business-visible outcome

The new applications use the familiar POC visual language through one responsive, accessible shared theme rather than blue/teal app-local styling.

## In scope

- Replace the current default blue/teal tokens with the Unified POC Brand: Inter, Space Grotesk, JetBrains Mono, neutral/dark surfaces, red accent, accessible light surfaces, POC-style cards, badges, borders, radii, shadows, spacing and loading states.
- Add semantic background, surface, dark-surface, action, hover, focus, text, border, status, radius, shadow, breakpoint, touch-target and reduced-motion tokens.
- Update shared UI and public CSS to consume semantic variables; do not add literal colors, fonts or arbitrary spacing to feature pages.
- Preserve responsive phone/tablet/desktop behavior and safe PWA behavior.

## Explicitly excluded

- Changing business behavior, API contracts, authorization, calculations or POC source.
- Pixel-copying unsafe markup or deciding final brand/legal content.
- Adding the alternate theme; that is D01-P01-T012.

## Architectural boundaries and owned paths

Owned paths: `packages/theme/**`, approved shared token CSS, shared UI token consumption and relevant theme tests. Do not edit another task’s owned paths without recorded approval.

Theme definitions are the only place for concrete visual values. Feature packages consume semantic roles through `packages/ui` and `packages/theme`.

- Keep theme state independent from server data, authorization, PWA cache policy and business calculations.
