## Requirements and rules

**Global i18n Architecture:** The CarChief application must support multiple languages to cater to a global customer base.
- Implement an internationalization (i18n) library (e.g., `next-intl`, `react-i18next`, or equivalent).
- Add a language switcher to the global menu bar allowing users to change their preferred language.
- The language preference must be persisted across sessions (e.g., via cookies or user profile).

**Google Translate Integration:** 
- Due to the high volume of dynamic vehicle data and user-generated content, manual translation files will not be sufficient for all content.
- Integrate Google Translate API (or the automated Google Translate website widget, wrapped gracefully via i18n) to provide automated translation for dynamic text, while keeping static UI strings (menus, buttons) in local i18n dictionaries.

## Business-visible outcome

Users visiting CarChief from non-English speaking regions can instantly switch the application into their native language. This removes language barriers, significantly improves trust, and opens the marketplace to a wider global audience, directly increasing conversion rates in emerging markets.

## In scope

- `apps/public-web/` & `apps/customer-app/`:
  - Install and configure the selected i18n library.
  - Setup routing to support locale prefixes (e.g., `/en/allstock`, `/ja/allstock`) if required by the chosen architecture.
  - Create the initial localization dictionaries (`en.json`, `ja.json`, `es.json`, etc.) for static UI elements.
  - Add a language selection dropdown to the global Header.
