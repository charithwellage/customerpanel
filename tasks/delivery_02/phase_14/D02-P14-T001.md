## Requirements and rules

**Dynamic Data Policy:** Bank information must NOT be hardcoded in the frontend. It must be fetched from the database via an API endpoint, as the details are subject to change over time.

**Access Control Policy:** Bank details must ONLY be visible to logged-in users. Do not show bank details to anonymous or unauthenticated users to prevent scammers from accessing this sensitive information.

**Visuals Policy:** Display the official bank logos (SMBC, MUFG, ADCB) next to their respective accounts.

## Business-visible outcome

When a customer navigates to the "How to Buy" page, they will see a secure payment section showing official bank accounts (SMBC, MUFG, ADCB) and PayPal details. These details are dynamically fetched from the server. If the user is not logged in, the bank details are hidden entirely.

## In scope

- `apps/mock-api/src/store.ts`:
  - Add seed data for the bank accounts (SMBC USD/JPY, MUFG USD/JPY, ADCB USD).
  - Add methods in `MemoryStore` and `PostgresStore` to retrieve bank information.
- `apps/mock-api/src/server.ts`:
  - Create a new endpoint `GET /api/v1/bank-accounts` to fetch the bank details.
  - Require authentication (401 if unauthenticated) for this endpoint.
- `apps/public-web/src/features/public-content/components/HowToBuyExperience.tsx`:
  - Fetch the bank details from the new API.
  - Conditionally render the bank details block based on whether the user is logged in (using `useSession` or the equivalent authentication hook).
  - Add the official bank logos to the UI using next/image or standard img tags.
- `apps/public-web/src/features/public-content/how-to-buy.css`:
  - Ensure styles match the premium CarChief design system layout for the payment section.

## Explicitly excluded

- Modifications to endpoints other than the new bank details API.
- Changes to user authentication logic (rely on existing session management).
