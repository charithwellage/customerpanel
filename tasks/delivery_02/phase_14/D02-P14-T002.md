## Requirements and rules

**Menu Bar Usability Policy:** The global menu bar (header) must be redesigned to emulate top-tier e-commerce platforms (e.g., Amazon, Noon.com). The goal is to provide a psychologically engaging, user-friendly interface that accelerates the car purchase journey from the very first impression.

**Global Search Integration:** The menu bar must incorporate a robust global search and filter interface accessible from any page.
- Required filters to include in the global search interface:
  - Price range
  - Discount percentage
  - Mileage
  - Year
  - Make

## Business-visible outcome

Customers will see a rich, e-commerce-style navigation bar at the top of the application. They will be able to immediately search for vehicles and filter by Make, Year, Price Range, Mileage, and Discount Percentage directly from the header without needing to navigate to a dedicated search page first. This reduces friction and increases conversion rates.

## In scope

- `apps/public-web/src/components/layout/` (or wherever the global Header/Navbar component resides):
  - Redesign the header layout to accommodate a prominent search bar.
  - Implement a rich search/filter dropdown or mega-menu that captures the specified filter criteria.
- State Management: Ensure search parameters entered in the menu bar correctly route the user to the `/allstock` (or equivalent inventory page) with the selected filters applied as URL query parameters.
- Ensure the header remains fully responsive (mobile-friendly).

## Explicitly excluded

- Modifying backend search algorithms (rely on existing API filter capabilities).
- Redesigning pages other than the global menu bar/header component.

## Architectural boundaries and owned paths

- Owned paths: Global layout components (`Header.tsx`, `Navigation.tsx`), global CSS files, and related UI components in the `ui` package or `public-web` app.

## Contract and incremental mock work

- No new API contracts are strictly required if the search page already accepts these query parameters. If the mock-api does not support filtering by `discountPercentage`, it must be added to the mock-api vehicle list endpoints.

### Frontend API integration

- The search bar should gracefully construct query parameters (e.g., `?make=Toyota&minYear=2018&maxPrice=15000`) and push the route to the inventory search page.

## Implementation and UX requirements

- Emulate Amazon/Noon UI paradigms: Prominent search input, categorized dropdowns, and clean, high-contrast action buttons.
- The search bar must look completely integrated and premium, using the `@carchief/theme` variables.
