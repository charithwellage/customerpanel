## Requirements and rules

**Quote Request Flow:** When a user clicks "Get Free Quote" on a vehicle details page, the system must enforce authentication before showing the quote calculator.
- **Anonymous Users:** Must be prompted to sign in (offering SSO providers like Google, Apple). Once this sign-in is complete, or if they create a new user account, they MUST be redirected seamlessly back to that exact same car page they were viewing to get the free quote. The system must not drop them on a generic dashboard.
- **Authenticated Users:** Should immediately see the quote calculator UI. The UI should be presented using an enterprise-grade method (e.g., a rich modal/popup overlay or a dedicated slide-over panel) without losing the context of the vehicle page.

**Quote Calculator UI:** The quote details interface must allow users to configure:
- Shipping Destination (Country).
- Port/City selection and Shipping Method (e.g., RORO vs Container) with dynamic pricing.
- Additional Options (Marine Insurance, Warranty).
- Discount Coupon Code input.
- Real-time Total Price calculation (e.g., C&F Total).

## Business-visible outcome

Customers browsing vehicles can easily request a quote. The business secures customer leads by enforcing sign-in before providing the detailed quote calculator. The calculator itself is transparent, allowing customers to toggle shipping methods and warranties to see exactly how their final C&F price is calculated.

## In scope

- `apps/public-web/src/features/vehicles/` (or wherever the vehicle details component resides):
  - Add the "Get Free Quote" CTA button.
  - Implement authentication boundary checks on button click.
- `apps/public-web/src/features/auth/`:
  - Ensure the sign-in redirect supports a `returnTo` URL parameter so users are sent directly back to the quote popup after signing in via Google/Apple.
- `packages/vehicle-detail/` (or a new UI package for quotes):
  - Build the `QuoteCalculatorModal` component matching the provided design requirements (Destination, Shipping Method, Options, Total Price).
  - Implement local state for calculating the total price dynamically as checkboxes/radio buttons are toggled.

## Explicitly excluded

- Submitting the final quote to the backend (this is handled by the `enquiries` contract in Phase 13). This task focuses purely on the UI presentation and authentication flow to *access* the quote.
- Implementing the actual OAuth backend strategies (rely on existing authentication infrastructure).

## Architectural boundaries and owned paths

- Owned paths: Components within `packages/vehicle-detail/` or a dedicated quote package, and route handlers in `apps/public-web` related to the vehicle details page and auth redirects.
