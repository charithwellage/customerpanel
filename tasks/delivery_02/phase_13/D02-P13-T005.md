## Business-visible outcome

A signed-in customer viewing a vehicle in the Customer application can request a quote with one click and can save the vehicle to their wishlist, from the same page.

## In scope

- Extend `apps/customer-app/src/features/inventory/CustomerVehicleDetailPage.tsx` (and its `useCustomerVehicleDetail.ts` hook only as needed to expose the vehicle slug/id it already loads) with two new co-located components:
  - `QuoteRequestButton.tsx` — on click, calls `EnquiryService.submit({ name: user.name, email: user.email, phone: profile.mobileNumber, message: '<fixed default quote-request message>', consent: true, vehicleSlug, enquiryType: 'price-request', source: 'form' })` via `useCustomerShell()`'s session and a `GET /api/v1/customer/profile` read; shows a brief in-progress state, then a persistent "Quote requested" confirmation state; remains clickable afterward so a repeat request is always possible with no error.
  - `WishlistToggleButton.tsx` — on click, calls `WishlistService.add(vehicleSlug)`/`WishlistService.remove(vehicleSlug)` (from T003) depending on current state; reflects the current wishlist state on page load via `WishlistService.list()` and persists visibly across reloads.
- Place both buttons in the same action area on the detail page, following the existing button/action styling conventions already used elsewhere on this page.

## Explicitly excluded

- Any nav item, new page, or route beyond the existing `/inventory/:slug`; T006/T007 own the new pages and nav entries.
- Any Mock API or contract change; this task only consumes T001–T003's existing contract.
- `apps/customer-app/src/features/vehicles/CustomerFleetDetailPage.tsx` — this task does not touch the already-owned-vehicle detail page.

## Contract and incremental mock work

### Frontend API integration
