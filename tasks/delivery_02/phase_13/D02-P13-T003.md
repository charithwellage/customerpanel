## Business-visible outcome

Both applications have a typed, validated path to every new endpoint from T001/T002, so subsequent UI tasks only wire components to existing services and hooks.

## In scope

- `packages/validation/src/enquiry.ts`: confirm the existing `enquiryFormSchema` already validates name/email/phone as mandatory (it does); add `quoteRequestFormSchema = z.object({ name, email, phone })` in the same file, trimmed to exactly those three fields, for the on-page quote actions in T004/T005 to use instead of the full contact-form schema.
- New `packages/validation/src/wishlist.ts`: `wishlistToggleSchema = z.object({ vehicleSlug: z.string().trim().min(1) })`.
- New `packages/validation/src/favourites.ts`: `favouriteSearchCriteriaSchema` mirroring `FavouriteSearchCriteria` field-for-field, with a `.superRefine()` cross-field check that `yearFrom <= yearTo`, `priceFromUsd <= priceToUsd` and `mileageMin <= mileageMax` when both sides of a pair are present; `favouriteSearchCreateSchema = z.object({ name: z.string().trim().min(1).max(80), criteria: favouriteSearchCriteriaSchema }).superRefine(...)` enforcing that at least one `criteria` field is non-empty (`D02-ASM-010`).
- `packages/validation/src/index.ts`: barrel-export the new schemas; add a sync test if any new enum literal tuple is introduced that must mirror a `packages/domain` array, following the existing `ENQUIRY_SOURCE_VALUES` convention.
- New `packages/api-client/src/services/customerInquiries.ts`: `CustomerInquiryService` with `list(): Promise<CustomerInquiryListResponse>` and `getVehicleInquiryCount(vehicleSlug: string): Promise<VehicleInquiryAggregate>`.
- New `packages/api-client/src/services/wishlist.ts`: `WishlistService` with `list()`, `add(vehicleSlug)`, `remove(vehicleSlug)`.
- New `packages/api-client/src/services/favourites.ts`: `FavouritesService` with `list()`, `create(name, criteria)`, `remove(id)`, `getFacets()`.
- `packages/api-client/src/index.ts`: barrel-export the three new services alongside the existing ones.
