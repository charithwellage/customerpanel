## Business-visible outcome

Any visitor on a public-web vehicle detail page can request a free quote by supplying name, email and mobile number, and can do so again for the same vehicle without ever seeing an error.

## In scope

- New `apps/public-web/src/features/quote-request/` (mirrors `features/reservation/`'s structure): `QuoteRequestSection.tsx` (section shell + trigger), `QuoteRequestAction.tsx` (the form itself), `useQuoteRequest.ts` (submission hook using `EnquiryService.submit()` and `quoteRequestFormSchema` from T003), `quote-request.css`, `index.ts`.
- Wire `<QuoteRequestSection vehicleSlug={...} />` into `apps/public-web/src/features/vehicle-detail/VehicleDetailPage.tsx`, positioned alongside the existing `<ReservationSection>` and the CTA bar's "Request Price" link — both remain; this is an additional, on-page, repeatable action, not a replacement.
- Form: `react-hook-form` + `zodResolver(quoteRequestFormSchema)`; fields are name, email, mobile only. On submit, calls `EnquiryService.submit({ name, email, phone: mobile, message: '<fixed default quote-request message>', consent: true, vehicleSlug, enquiryType: 'price-request', source: 'form' })`.
- Success state: an inline confirmation replacing the form, dismissible, with a "Request another quote" affordance that re-opens the form (the mandatory fields are not required to persist between requests).

## Contract and incremental mock work

No Mock API or OpenAPI change is owned. Consume `EnquiryService.submit()` and `quoteRequestFormSchema` from `D02-P13-T003`.

### Frontend API integration

Submission goes through `EnquiryService.submit()`, which itself goes through `HttpClient` and the public-web browser-side proxy at `src/app/api/v1/[...path]/route.ts` — the browser never calls the Mock API origin directly. Render explicit loading, validation (each field's own message), network-error and success states; a repeat submission always renders the same success state, never an error.

## Implementation and UX requirements

- Read and follow [COMMON_FRONTEND_RULES.md](../../COMMON_FRONTEND_RULES.md).
- Support 390x844, 768x1024 and 1440x900, full keyboard operation, visible focus, contrast and reduced motion.
- Every input has a persistent visible label, an `autocomplete` attribute (`name`, `email`, `tel`) and an `aria-describedby` error association.
- The submit control is disabled while in flight and the form is not resubmittable by a double click.
- Errors are announced to assistive technology through a live region as well as inline.
