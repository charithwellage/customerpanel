## Requirements and rules

**Delivery 02 execution policy:** Run the task-owned tests and dependency-closure build named under **Validation commands**. Do not edit another task's owned paths.

**Phase 2.13 identity policy.** Every wishlist and favourite row is scoped to `resolveCustomerScope(req.user.sub)`, resolved server-side; a client never supplies its own customer id. A customer can never read, create for or delete another customer's rows.

**Favourites data-honesty policy.** `GET /api/v1/customer/favourites/facets` returns only distinct values that actually exist in `vehicles` data. ## Business-visible outcome

A signed-in customer can save a specific vehicle to a wishlist and can create up to 25 reusable saved-search-criteria favourites, with every favourite dropdown backed by real inventory data.

## In scope

- `packages/domain/src/index.ts`: add `WishlistItem { id, customerId, vehicleId, vehicleSlug, createdAt }`, `WishlistListResponse { items: WishlistItem[] }`, `WishlistToggleRequest { vehicleSlug }`, `WishlistToggleResponse { wishlisted: boolean, item?: WishlistItem }`; add `FavouriteSearchCriteria { make?, model?, modelCode?, yearFrom?, yearTo?, priceFromUsd?, priceToUsd?, mileageMin?, mileageMax?, engineCc?, fuelType?, color?, steering?, driveTrain?, transmission? }` (all optional), `FavouriteSearch { id, customerId, name, criteria: FavouriteSearchCriteria, createdAt }`, `FavouriteSearchListResponse { items: FavouriteSearch[], limit: number }`, `FavouriteSearchFacets { makes, models, fuelTypes, driveTrains, transmissions, yearRange, priceRange, mileageRange, modelCodes, engineCcOptions, colors, steeringOptions }` where the last four fields are documented as returning an empty array today per `D02-ASM-008`.
- `apps/mock-api/src/store.ts`:
  - New Postgres tables (both brand new, so plain `CREATE TABLE IF NOT EXISTS` is sufficient): `wishlist_items (id text PRIMARY KEY, customer_id text NOT NULL, vehicle_id text NOT NULL, vehicle_slug text NOT NULL, created_at text NOT NULL, UNIQUE(customer_id, vehicle_id))` and `favourite_searches (id text PRIMARY KEY, customer_id text NOT NULL, name text NOT NULL, criteria_json text NOT NULL, created_at text NOT NULL)`.
  - `MemoryStore` equivalents backed by in-memory arrays, consistent with how every other customer-domain entity is implemented in that class today.
  - New `DemoStore` methods in both stores: `listWishlist(customerId)`; `toggleWishlist(customerId, vehicleSlug)` — idempotent add/remove, 404 if the vehicle slug does not exist; `listFavourites(customerId)`; `createFavourite(customerId, name, criteria)` — rejects an all-empty `criteria` with a typed validation error (`D02-ASM-010`), and rejects the 26th favourite for one customer with a typed limit error (**the authoritative cap-enforcement point** for CUST-40) — this method is the only place the cap is enforced; `deleteFavourite(customerId, id)` — 404 if the id does not belong to that customer; `getFavouriteFacets()` — extends the existing `calculateFacets()` (`apps/mock-api/src/store.ts`, distinct-values computation already powering vehicle search) to also compute `models`, `fuelTypes`, `driveTrains`, `transmissions`, `yearRange` and `mileageRange` from real `VehicleRecord` data, and returns empty arrays for `modelCodes`, `engineCcOptions`, `colors`, `steeringOptions`.
  - `reset()` in both stores clears `wishlist_items` and `favourite_searches`.
- `apps/mock-api/src/server.ts`, all requiring `req.user` (401 if absent) and scoped via `resolveCustomerScope`:
  - `GET /api/v1/customer/wishlist` — `WishlistListResponse`.
  - `POST /api/v1/customer/wishlist` — body `WishlistToggleRequest`; 200 `WishlistToggleResponse`; 404 if the vehicle does not exist.
  - `DELETE /api/v1/customer/wishlist/:vehicleSlug` — 200 `WishlistToggleResponse` with `wishlisted: false`; idempotent if not present.
  - `GET /api/v1/customer/favourites` — `FavouriteSearchListResponse`.
  - `POST /api/v1/customer/favourites` — body `{ name, criteria }`; 201 `FavouriteSearch`; 400 on empty criteria; 409 with `reason: 'limit_exceeded'` at the 25-favourite cap.
  - `DELETE /api/v1/customer/favourites/:id` — 204; 404 if the id does not belong to the caller.
  - `GET /api/v1/customer/favourites/facets` — `FavouriteSearchFacets`.
