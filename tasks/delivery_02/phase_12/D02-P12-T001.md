**Phase 2.12 identity policy.** The Mock API is the only authority for credentials and sessions. A password is never stored, logged, cached or returned in plaintext; a password hash never leaves the server. The browser never derives authorization from its own state. `DEC-CUST-IDENTITY-RECOVERY` is unchanged: AutoPulse/Keycloak still owns production identity, and this phase supplies a Keycloak-compatible mock credential path, never a claim of live identity, email delivery or MFA.

## Business-visible outcome

A visitor can create a real CarChief customer account, sign in with those credentials, change the password and complete a password reset, all enforced by the Mock API.

## In scope

- Add a `customer_accounts` entity to `apps/mock-api/src/store.ts` in **both** `MemoryStore` and `PostgresStore`: id, customer id, name with initials, country code, dial code, mobile number, email (unique, case-insensitive), password hash, password salt, status, created/updated timestamps and password-updated timestamp.
- Add a `password_reset_outbox` entity holding the reset token, target email, issued/expiry timestamps and consumed flag.
- Hash passwords with salted `scrypt` from `node:crypto`. Never store, log or return a plaintext password or a hash.
- Seed exactly one registered credential bound to the existing fixture customer `cust-123` so every existing Delivery 02 customer suite keeps a working identity. Seed the exception fixture customer the same way if its suites require a session.
- Add routes to `apps/mock-api/src/server.ts`:
  - `POST /api/v1/auth/register` — 201 with the created account projection (no credential material) or 400 with a `field` for the first invalid input; 409 on duplicate email.
  - `POST /api/v1/auth/login` — 200 with `{ token, claims }` or 401 with one generic message for both unknown email and wrong password.
  - `POST /api/v1/auth/change-password` — authenticated; 400 on policy failure, 401 when the current password is wrong.
  - `POST /api/v1/auth/password-reset` — always 202 regardless of whether the email exists (no account enumeration); writes a single-use expiring token to the outbox.
  - `POST /api/v1/auth/password-reset/confirm` — consumes the token, applies the new password, invalidates the token.
  - `GET /api/v1/config/countries` — the country, ISO code and E.164 dial-code list.
  - `GET /api/v1/auth/__outbox` — non-production only; returns 403 when `NODE_ENV=production`, mirroring the guard on `POST /api/v1/__reset`.
- Replace `resolveDemoCustomerScope` in `apps/mock-api/src/auth/customer-scope.ts` with `resolveCustomerScope`, which maps a registered account subject to its own customer id and keeps the seeded fixture mapping. It still never accepts a customer id from the browser.
- Remove `POST /api/v1/auth/demo-session` and every route comment that presents the mock as a demo identity.
- Include `POST /api/v1/__reset` coverage so a reset restores the seeded credential and clears registered accounts and outbox rows deterministically.
