**Phase 2.12 identity policy.** The Mock API is the only authority for credentials and sessions. A password is never stored, logged, cached or returned in plaintext; a password hash never leaves the server. The browser never derives authorization from its own state. `DEC-CUST-IDENTITY-RECOVERY` is unchanged: AutoPulse/Keycloak still owns production identity, and this phase supplies a Keycloak-compatible mock credential path, never a claim of live identity, email delivery or MFA.

Shared code lives in the narrowest correct owner. Validation schemas are a UX convenience only; the Mock API stays the authoritative validator, and every schema field name matches the API contract one-to-one so a server 400 `field` maps straight onto a form error.

## Business-visible outcome

Both applications draw the country list, password rules and authentication calls from one shared source, so registration and sign-in cannot drift apart.

## In scope

- `packages/domain`: add the ISO-3166 country dataset with the country name, ISO alpha-2 code and E.164 dial code, plus a lookup helper. Rename `createDemoJwtToken` to `issueSessionToken` with unchanged behaviour, delete `DemoSessionResponse`, and keep `parseDemoJwtToken` behaviour under a non-demo name. Update `packages/domain/src/index.ts` and `packages/domain/src/__tests__/auth.test.ts`.
- `packages/validation`: add `registrationFormSchema`, `loginFormSchema`, `passwordChangeSchema` and `passwordResetSchema` following the shape of `src/enquiry.ts` — flat fields, `superRefine` for the password-confirmation match, and the documented note that the server remains authoritative. Encode exactly the password policy that `D02-P12-T001` implemented.
- `packages/api-client`: add `AuthService` (register, login, changePassword, requestPasswordReset, confirmPasswordReset) and `CountryService`, following the constructor-injected `requireClient()` shape of `src/services/customerProfile.ts`. Delete `SessionService.startDemoSession`.
- Note the existing base-URL asymmetry: public-web services use full `/api/v1/...` paths while customer-app services use paths relative to a `/api/v1` base URL. Make each new service explicit about which convention it follows and document it in a comment.

## Contract and incremental mock work

No new Mock API route is owned. Consume the schema regenerated by `D02-P12-T001`; if a required type is missing, reopen `D02-P12-T001` rather than hand-editing `packages/api-client/src/generated/schema.d.ts`.

### Frontend API integration

Every new call goes through `HttpClient`, inherits the correlation-id header, bearer-token callback and timeout, and surfaces failures as `NormalizedApiError`. A 400 carrying a `field` must reach the caller intact so a form can attach the message to that input. A 401 from login is returned as a normalized error, never as `null`.

## Implementation and UX requirements

- Read and follow [COMMON_FRONTEND_RULES.md](../../COMMON_FRONTEND_RULES.md).
- Validation messages are written for an end user, name the offending field and never echo the submitted password.
- The country dataset must be usable at phone width: the payload stays small enough to render in one request without a loading spinner chain.
