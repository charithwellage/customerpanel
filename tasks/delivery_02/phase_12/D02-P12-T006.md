## Architectural boundaries and owned paths

- Owned paths: `apps/customer-app/src/features/profile/**`, plus the named demo-copy removals in `payments`, `invoices` and `src/app/App.tsx`.
- Features must not import `api-client/generated/schema`; go through `CustomerProfileService` and `AuthService`.
- A successful password change must not silently invalidate the current session unless the Mock API says so; render whatever the server actually returns.

## Contract and incremental mock work

No Mock API or OpenAPI change is owned. Consume `POST /api/v1/auth/change-password` and the existing `GET`/`PUT /api/v1/customer/profile` contract.

### Frontend API integration

The change-password submission goes through `AuthService.changePassword` with the bearer token supplied by `HttpClientProvider`. A 401 means the current password was wrong and renders on that field, not as a session expiry. A 400 with a `field` attaches to that input. Profile edits keep sending `expectedVersion` and keep the 409 refresh path.
