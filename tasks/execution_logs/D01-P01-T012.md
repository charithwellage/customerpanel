This contradicts CONTEXT.md section 2 and TASK_EXECUTION_PROTOCOL.md Profile A's documented guidance that a process restart alone is sufficient to switch themes -- true only for dynamic (ƒ) routes. tests/e2e/theme-parity.spec.ts cannot catch this: its only data-theme assertion (line 274) targets '/' exclusively, and the structural-fingerprint comparison is colour-blind by design, so 63/63 passed on both themes despite the defect. Fix is outside D01-P09-T002's token/stylesheet-only scope: it requires either 'export const dynamic = force-dynamic' on the 3 affected page.tsx files or a theme-resolution mechanism in layout.tsx (owned by D01-P01-T012, which introduced resolveThemeId(process.env.NEXT_PUBLIC_THEME_ID) in layout.tsx, commit 0f93eda) that survives static optimization. Evidence screenshots: .playwright-mcp/FINDING-vehicles-stuck-carchief.png, FINDING-account-stuck-carchief.png, FINDING-freight-stuck-carchief.png (all captured against a live NEXT_PUBLIC_THEME_ID=ocean server, all render carchief red/black/orange, not ocean navy/blue).
