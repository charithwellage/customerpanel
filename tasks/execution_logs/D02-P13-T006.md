## Fix pass — 2026-08-18 (Finding 2 closure)

### Root causes found and fixed

1. `signIn()` waited on `page.getByRole('heading', { name: 'Customer Portal' })`, which does not exist in the rendered shell (it renders a sidebar link with that text, not a heading). Fixed to `page.waitForSelector('.cc-cust-shell-layout', ...)`, the real always-present shell wrapper (confirmed by reading `CustomerShell.tsx`).
2. The "request quote from inventory" test used `page.getByTestId('request-quote-btn')`, a testid that does not exist anywhere in the codebase; the real button (added by T005) is `data-testid="quote-request-btn"`. The quote was silently never requested, so the "after requesting a quote" test only passed when unrelated leftover data existed.
3. The success-banner assertion checked for "Quote requested successfully"; the real banner text is "Quote Requested" (`CustomerVehicleDetailPage.tsx`).
4. This suite's tests share one account. Registering a fresh, uniquely emailed account per test via `POST /api/v1/auth/register` (the `account-access.spec.ts` precedent) — rather than the single shared fixture account plus a global `POST /api/v1/__reset` — avoids the cross-project data race a shared account + reset produces when the three viewport projects run concurrently under `--workers=50%` (confirmed empirically: the reset-based version intermittently failed "empty state" assertions when another project's reset fired mid-test). A freshly registered account's profile phone defaults to `''`, and quote submission requires a non-empty phone, so the helper also sets it via `PUT /api/v1/customer/profile` right after registering.
