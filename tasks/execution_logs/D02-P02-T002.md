## Decisions and deviations

- **HttpClientProvider Pattern**: Implemented as a new provider wrapping the CustomerShell to supply HttpClient context to all features. This follows the established provider pattern used by AccountGuard and supports future feature development (payments, shipments, etc.) without repeated client instantiation.

- **TanStack Query Configuration**: Set staleTime to 5 minutes and gcTime to 10 minutes to balance freshness with caching. Retry set to 1 to avoid double-failures for transient errors. throwOnError enabled to surface errors to ErrorBoundary when appropriate.

- **Card Component Granularity**: Created 6 distinct card components (Credit, Vehicles, Payments, Shipments, Documents, Notifications) rather than a single monolithic view. This enables future reuse, independent testing, and incremental feature development.

- **Partial Failure Display**: Implemented as a conditional alert below the grid. Only shown when any linked-record query failed, preserving the original design intent (cached data is better than no data).

- **API Generation Build Step**: Updated `packages/api-client/package.json` build script to copy generated directory to dist. This ensures the schema.d.ts declaration file is available at module resolution time for TypeScript consumers.

- **CSS-in-Card Styling**: All progress bar, count label, and status colour logic lives in dashboard.css using semantic classes. No style attributes in JSX. Colour modifiers (--status-color) are applied via BEM variants (--approved, --pending, --rejected, etc.).
