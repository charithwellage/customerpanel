Treated as a naming inconsistency in the task file, not a scope expansion — no new decision-gate dependency was added.
- **`useEnquiryForm` keeps a props-driven `EnquiryForm` contract**: this repository's root `vitest.config.ts` runs with `environment: 'node'` (no jsdom/`@testing-library`), so every existing component test in this feature area (D01-P05-T004's original suite) asserts static `renderToStaticMarkup` output rather than simulating user interaction. `react-hook-form`'s `useForm` genuinely drives validation/submission/error-state inside `useEnquiryForm` (satisfying "Build ... forms with RHF/Zod"), but `EnquiryForm` itself stays a plain controlled component (`values`/`onFieldChange`/`fieldErrors` props) rather than spreading `register()` onto inputs, so it remains testable under the existing no-DOM harness without inventing a new jsdom dependency outside this task's scope. Documented here rather than filed as a `REQUIREMENT_GAPS_AND_ASSUMPTIONS.md` entry because it is a testing-infrastructure implementation choice, not a business-rule gap.
- **Vehicle-preference fields as flat, optional `EnquiryRequest` properties** (`preferredMake`/`preferredModel`/`preferredDriveSide`/`preferredYear`/`targetPriceUsd`) rather than a nested object: the task file's "Where approved, capture vehicle-preference fields ... and contact-source intent" carries no specific field-shape decision, and `decision_gates: []` confirms no gate blocks this; flat fields keep the server 400 `field` value mapping directly onto the matching RHF field with no translation table, consistent with the existing `EnquiryRequest` shape's own flatness. No new entry was added to `REQUIREMENT_GAPS_AND_ASSUMPTIONS.md` since this is UI/contract-shape data capture, not a business rule.
- **Preferred contact method reuses the existing `source` field** (`D01-P06-T001`) rather than introducing a second field: the mock already accepts and persists an explicit `source`; the form now lets the visitor set it directly (labelled "Preferred contact method"), and `EnquiryConfirmation` states plainly that no automatic message is sent for a non-form choice (RULE-10, `DEC-WF-EXTERNAL-BOUNDARIES` unaffected — still `OPEN`, still no delivery implemented).
