### Real root cause (per `tasks/execution_logs/D01-P08-CODE_REVIEW.md` Finding 1)

`docker-compose.frontend.yml` set `NODE_ENV: production` for the `mock-api` service with no `ENABLE_MOCK_RESET` override. The mock-api guard at `apps/mock-api/src/server.ts:344` (`if (process.env.NODE_ENV === 'production' && process.env.ENABLE_MOCK_RESET !== 'true')`) correctly blocks `POST /api/v1/__reset` under exactly that condition as an intentional production-safety feature (independently proven by D01-P08-T002's `build:production`/`test:production-guard` and the real-HTTP-route tests in `apps/mock-api/src/__tests__/security-projection.test.ts`). But `enquiry-reservation.spec.ts` and `freight-enquiry.spec.ts` call this endpoint in `beforeEach` for test isolation. Blocked with a silent 403, state accumulated across tests, producing non-deterministic duplicate/conflict/ceiling failures — this task's own original run saw 206/228 (22 failed); the phase review's independent fresh-container rerun saw a worse 198/228 (30 failed), confirming the pollution compounds and the suite is non-deterministic run-to-run under the broken configuration.
